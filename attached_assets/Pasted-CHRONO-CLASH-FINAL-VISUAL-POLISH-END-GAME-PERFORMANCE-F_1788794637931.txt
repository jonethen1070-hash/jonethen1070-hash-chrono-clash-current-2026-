==================================================

There is a small but noticeable slowdown immediately before the Victory or Defeat screen appears.

Find the actual cause of the end-of-match performance spike.

Inspect:
- final match resolution
- final cascade
- gem destruction effects
- particle effects
- Mega Strike effects
- Energy Burst effects
- screen shake
- screen flash
- glow/filter effects
- score calculation
- timer shutdown
- animation loops
- requestAnimationFrame

- DOM creation/removal
- CSS filters
- VFX cleanup
- Victory/Defeat overlay creation

The end-game sequence must work like this:

FINAL GAMEPLAY ACTION
→ determine result immediately
→ stop gameplay processing
→ clean up/cancel expensive temporary VFX
→ show Victory/Defeat screen
→ play only lightweight result animation

Do NOT make the game wait for VFX to finish before showing the result.

Do NOT add a long transition.

The desired feeling is:

FINAL MOVE
→ tiny impact
→ INSTANT RESULT
→ smooth Victory/Defeat screen

Any temporary VFX that are still running when the match ends should be safely cancelled, reused, or reduced.

Make sure VFX do not accumulate.

Every temporary effect must have proper cleanup.

Do not allow:
- abandoned animation frames
- abandoned timers
- duplicate event listeners
- particles that remain alive
- invisible DOM elements accumulating
- repeated full-screen effects
- multiple simultaneous screen-shake loops
