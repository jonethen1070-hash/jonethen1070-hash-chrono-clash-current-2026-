================================================
1. REMOVE FIXED-VIEWPORT DEPENDENCY
================================================

Find and eliminate any layout rules that assume:

390px × 844px

or another specific phone size.

Do NOT simply scale the entire game with one giant transform.

Instead make the individual sections responsive.

The game should calculate available vertical space dynamically.

Use modern viewport units where appropriate:

100dvh
100svh
100lvh

and account for:

env(safe-area-inset-top)
env(safe-area-inset-bottom)
env(safe-area-inset-left)
env(safe-area-inset-right)

Do not rely exclusively on 100vh because mobile browser UI can make it inaccurate.

================================================
2. CREATE A REAL GAME VIEWPORT
================================================

The game root should occupy the available screen:

width: 100%;
height: 100dvh;
min-height: 100svh;

and:

overflow: hidden;

The page itself must NOT scroll.

The game must remain inside the visible viewport.

Do not allow the browser document to become taller than the device.

================================================
3. SAFE AREA
================================================

Respect phone safe areas.

Use:

padding-top: env(safe-area-inset-top);
padding-bottom: env(safe-area-inset-bottom);

where necessary.

But DO NOT create huge empty spaces.

The playable composition should use the remaining space efficiently.

================================================
4. RESPONSIVE VERTICAL COMPOSITION
================================================

The screen should be treated as a flexible vertical layout.

Use something equivalent to:

GAME ROOT
├── HEADER
├── BATTLE HEADER
├── ATTACK
├── ENERGY
├── ABILITIES
├── BOARD
└── BOTTOM CONTROLS

The board must receive the largest amount of available space.

The other sections should shrink slightly when the device is shorter.

Do NOT shrink the board first.

================================================
5. BOARD MUST SCALE RESPONSIVELY
================================================

The 8×8 board remains EXACTLY 8×8.

Never change the number of rows or columns.

The board width should be:

min(
  availableWidth,
  availableHeight-based-size
)

The board must remain square.

The board must NEVER extend beyond:

left viewport edge
right viewport edge
top/bottom available game area.

On narrow phones:

reduce board size just enough to fit.

On wider/taller phones:

allow the board to become larger.

The board should use the maximum beautiful size that fits.

================================================
6. GEM SIZE MUST FOLLOW BOARD SIZE
================================================

Every gem must scale proportionally with the board.

Do NOT keep fixed gem dimensions while shrinking the board.

Do NOT let gems overflow their cells.

For every viewport:

8 columns × 8 rows
=
perfectly square grid.

All 64 gems must remain completely visible.

================================================
7. BOARD FRAME MUST FIT PERFECTLY
================================================

This is important.

The board frame must wrap the entire 8×8 grid perfectly.

No:

extra bottom gap
floating lower frame
cropped lower frame
uneven left/right spacing
gem touching frame

The frame must have symmetrical visual spacing around the complete grid.

The bottom of the board must end cleanly before the bottom control row.

================================================
8. BOTTOM CONTROLS
================================================

Freeze / Time Shift / Rewind MUST ALWAYS BE FULLY VISIBLE.

They must never be pushed below the screen.

They should occupy the remaining space after the board.

Keep them touch-friendly.

If the device is short:

reduce their vertical height.

Do NOT push them offscreen.

Do NOT hide their labels.

Do NOT make them microscopic.
